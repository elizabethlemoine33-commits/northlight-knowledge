# Organisational Clarity Framework

## Purpose
Improve execution by increasing organisational clarity.

## Step 0: Check the domain first
Before clarifying anything, ask whether this problem is complicated (cause and effect are knowable through analysis — proceed to Step 1) or complex (cause and effect are only knowable in retrospect — run small, safe-to-fail experiments first, and let outcomes, ownership, and measures clarify from what's learned, rather than imposing them upfront). Skipping this check risks manufacturing false confidence on a problem the organisation doesn't yet understand well enough to clarify.

### Client-facing version of the check

The internal research language (Cynefin, complicated vs. complex) doesn't belong in a client conversation. Use this instead, in order:

1. **"Have we solved basically this exact problem before?"** Yes → known territory. Run the full sequence below at full speed.
2. **"Is there a right answer, but it takes real digging or expertise to find it?"** Yes → still complicated, just slower. Get the analysis or the expert opinion first, then run the sequence.
3. **"Would even our best person here have to admit they're guessing?"** Yes → this is complex, not complicated. Clarifying outcomes, ownership, or measures now won't fix that — it manufactures confidence nobody's earned yet. Run something small and reversible instead, see what actually happens, and let clarity come from that.
4. **"Is something actively on fire right now?"** Yes → none of the above. Stop the bleeding first. Analysis and clarity both wait until the immediate damage is contained.

One-line version, if there's only room for one question: *"Do we already know the answer here, or do we need to try something small and see what happens?"* Known answer → run the framework. Don't know yet → probe before clarifying.

**If the initial read turns out to be wrong, reclassify and adjust — this is expected, not failure.** Starting in the wrong lane and noticing is part of the method. The domain check gets you to a starting line; observation during the engagement tells you whether you read the terrain correctly.

## Sequence
1. Clarify outcomes.
2. Clarify ownership.
3. Clarify decisions.
4. Clarify information flow.
5. Clarify measures.

## Expected Outcomes
- Faster decisions
- Less rework
- Better alignment
- Increased capacity

## Known limitation
This sequence is a complicated-domain tool. Applied to a genuinely complex problem before it's been probed, it can strip out variety (redundant roles, informal workarounds, unresolved ambiguity) the organisation may still need. See `EVD-EXT-0002` for the research behind this caveat.
