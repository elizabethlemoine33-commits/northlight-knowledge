# Privacy-First as Architecture — LinkedIn Posts

## Summary

Four posts articulating the privacy philosophy behind Northlight Vault and Northlight's product decisions more broadly. These posts function as both product explanation and principles statement. The personal post (May 21) adds a human origin story not present in the blog — Vault was built because file loss was a real problem. The page posts (June 2, June 23) are marketing-oriented and surface the "search all three cloud systems at once" functionality.

## Source

- Channel: Elizabeth Anne (Randell) Lemoine, LinkedIn personal + company page
- Retrieved via: Buffer API
- Date range: May 2026 – June 2026
- Post count: 4 substantive posts in this cluster

## Key Claims

- Vault was built because files kept getting lost across too many places — a personal problem before it became a product; "I built it for myself first"
- Vault searches all three major cloud systems (Google Drive, OneDrive, Dropbox) simultaneously — not a sync tool, not a storage layer, a unified search
- Privacy-first philosophy applied as architecture: no user data stored, no training on user files, Plausible Analytics only (privacy-respecting, no personal identifiers); "what do we actually need?" is the first question, compliance comes after
- "User trust is cumulative" — Vault earns trust through consistent behaviour: clear explanations for what it does and doesn't collect, visible consequences when data minimisation isn't possible, the ability to use the tool without surrendering data you weren't expecting to hand over
- Building alone means making intentional decisions about what to prioritize; three things that matter right now: shipping something that solves a real problem, making sure the people who need it can find it, and not building technical debt that will cost more to undo than it saved
- Privacy-by-design starts with data minimisation — not collecting what you can't explain
